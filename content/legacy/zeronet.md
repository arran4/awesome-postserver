# ZeroNet and successor projects

**Assessment:** Legacy distributed publishing ecosystem; no current recommendation or architecture verification.  
**Maturity:** Original project inactive; successor maintenance varies. **Reviewed:** 2026-11-19.

ZeroNet let users publish signed websites and replicate content between participating nodes using BitTorrent-like peer discovery. A ZeroNet client could both **view and serve** content, which makes it much more than a read-only web browser or a transient file transfer app.

## Original and successor source repositories

- [HelloZeroNet/ZeroNet](https://github.com/HelloZeroNet/ZeroNet) — original historical codebase; do not promote an abandoned project website as the primary link.
- [ZeroNetX/ZeroNet](https://github.com/ZeroNetX/ZeroNet) — fork with newer onion-service compatibility work.
- [zeronet-conservancy/zeronet-conservancy](https://github.com/zeronet-conservancy/zeronet-conservancy) — continuation/preservation project.

These are related but not interchangeable: check protocol compatibility, security updates, maintenance and community availability separately.

## Two-device question

Confirm that two ordinary installations can host, retrieve and retain a signed site in a private or direct-peering mode without a tracker, special permanent seeder or central site host. Distinguish ordinary distributed site persistence (which depends on at least one available holder of content) from mandatory dedicated infrastructure.

**No live test has been performed.** Until verified, keep this a historical page and do not infer that every fork is actively maintained.
