Networking foundations

Networking foundations Assessment: Supporting technologies. Reviewed: 2026-11-19. These tools can help build server-optional software, but networking a pair of machines is not equivalent to persisting or replicating meaningful application state. Technology Contribution Why it is not automatically a qualifying application WebRTC Peer sessions, ICE connectivity, optional TURN fallback No intrinsic persistent dataset or peer discovery/signalling policy; applications must supply these mDNS / DNS-SD LAN peer and service discovery Temporary cache of advertised records, not durable application data tinc Encrypted participant VPN mesh Routes packets but does not itself replicate application content Nebula Host-to-host encrypted overlay networking Typical dynamic discovery uses lighthouse nodes; direct static peers alone do not establish stateful functionality LibreMesh Software for distributed wireless routers Normally deployed on independently operated router hardware; not an ordinary end-user application Tor Onion Services Reachability through Tor network Client/service depends on Tor routing and directories, not just two standalone clients Inclusion boundary These technologies can appear within a platform’s ecosystem page or as implementation dependencies for qualifying applications.
